# Паспорт проекта

> Шаблон для заполнения на паре 5. Примеры в скобках — из эталона ShoeShop.
> Файл живёт в репозитории: `docs/passport.md`

## 1. Название проекта

True-Shop

## 2. Проблема

У нашего небольшого магазина самые простые функции которые могут работать не исправно. Покупатели не могут нормально заказать обувь, либо оплатить товар.

## 3. Пользователи

Администратор - может полностью менять приложение, изменять цену, отменять заказы, доступ к балансу за заказы и тд

Ассистент - роль которая дает человеку изменять цену, добавлять товар, удалять товар, помогать с заказами, нет доступа к балансу и тд

Рабочий - роль которая дается чтобы оповещать ассистента о поставках, добавляет товар, помогает с заказами

Обычный пользователь - имеет доступ купить товар, посмотреть товары, имеет в аккаунте счетчик когда придет его купленный заказ

## 4. Цель проекта

дать клиенту приятный интерфейс с возможностью попросить скидку на определнный товар, так же купить товар. А рабочему добавлять товары при поставках.

## 5. Метрики успеха

Приятный и простой интерфейс для того чтобы покупатель ЗАХОТЕЛ купить наш товар, так же сделать быструю оплату и выбор ближайшего пункта выдачи, и сделать актуальную рекламу с песней которая будет крутиться в голове.

## 6. Границы (что НЕ делаем)

не тратим весь бюджет на обувь, оставляем внезапные расходы. не покупаем рекламу в большом количестве.

## 7. Риски

Продвигаем через соц сети - заливер ошибается = понижении репутации. Положительный эффект = товары начинают покупать чаще, магазин начинает быть известным.

Покупка товара у непроверенных источников = риск - купить не качественный товар. Положительный = купить хороший товар за малое кол-во денег
